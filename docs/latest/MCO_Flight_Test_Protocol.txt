MCO FLIGHT TEST PROTOCOL
Metachronal Cascade Ornithopter — Rev A  2026-06-16
Based on: FAA AC 90-89C (2023)  |  EAA Flight Test Manual v2 (2024)
============================================================

PROGRAMME OVERVIEW
------------------------------------------------------------

The FAA requires all experimental aircraft to demonstrate:
  "The aircraft is controllable throughout its normal range of
   speeds and throughout all the maneuvers to be executed, and
   that the aircraft has no hazardous operating characteristics
   or design features."  (14 CFR §91.319(b))

For the MCO, this means demonstrating controllability across:
  • Full speed range (Vs to Vne)
  • Full altitude range (ground to service ceiling)
  • All flapping configurations (phase, amplitude, sweep, dihedral)
  • All loading conditions (minimum to MTOW)
  • All flight regimes (slow, cruise, sprint, climb, glide)

The MCO-1D drone is the PRIMARY test vehicle. Every limit is
first found on the drone before the MCO-1A piloted aircraft
is tested. This is not just good practice — it is the only
responsible approach for a novel flight configuration.

PHASE STRUCTURE (mirrors AC 90-89C chapter structure):
  Phase 1: Ground and taxi verification (TC-01 to TC-02)
  Phase 2: First flight — basic controllability (TC-03)
  Phase 3: Envelope expansion — all critical limits (TC-04 to TC-09)
  Phase 4: Performance and optimisation (TC-10 to TC-11)
  Phase 5: MCO-1A transition (TC-12 and beyond)

MCO-1D minimum Phase I: 40 hours (non-TC engine, per AC 90-89C)
MCO-1A minimum Phase I: 40 hours (non-TC engine, per AC 90-89C)

TEST CARD 01 — STATIC GROUND RUN — DRIVE SYSTEM VERIFICATION
Phase: PHASE 1 — GROUND  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Verify drive system, ODrive, and wing mechanisms operate correctly through full stroke range at all frequencies before any flight attempt.

PRECONDITIONS:
  ✓ Aircraft secured to ground anchors rated for 4× MTOW
  ✓ ODrive firmware configured (vel_limit=150, current_lim=36A)
  ✓ All 8 wings installed and free to move
  ✓ Telemetry link confirmed active
  ✓ All personnel behind safety line (≥3m from wing tips)

PROCEDURE:
  1. Spin up at f=0.5 Hz, AMP=60°. Verify all 8 wings respond symmetrically.
  2. Increase to f=1.0 Hz. Record ODrive current per axis.
  3. Increase to f=2.0 Hz. Check for vibration, rope slip, binding.
  4. Increase to f=3.0 Hz (MAX). Hold for 30 seconds. Record motor temperature.
  5. Reduce to 0 Hz. Inspect all rope runs, pulleys, and sector wheels.
  6. Repeat at AMP=96° (proposed sector wheel upgrade). Verify clearances.
  7. Test all sweep positions (0°, 60°, 90°, 120°, 210°) while flapping at 1 Hz.
  8. Test all dihedral positions (-20° to +60°) while flapping at 1 Hz.
  9. Execute CF-1 burst mode 3× at f=2.5 Hz. Record peak current.
  10. Full stop. Inspect all drive components for wear.

SUCCESS CRITERIA:
  ✓ All 8 wings respond symmetrically within ±5% of commanded amplitude
  ✓ Motor current at 3 Hz ≤ 30A (within limit with margin)
  ✓ No rope slip, binding, or sector wheel end-stop collision
  ✓ Estimated motor temperature rise ≤ 50°C after 30s at 3 Hz
  ✓ Telemetry data logged for all axes

ABORT CRITERIA (revert / RTB immediately):
  ✗ Any wing fails to move symmetrically
  ✗ Motor current exceeds 36A on any axis
  ✗ Rope slippage detected (velocity error > 10 rad/s on ODrive)
  ✗ Visible structural deformation in any component
  ✗ Smoke or burning smell from any motor or controller

DATA TO RECORD:
  → Current (A) per ODrive axis at each frequency
  → Peak current during CF-1 burst
  → Motor temperature estimate (MotorThermalMonitor output)
  → Position error (rad) per axis at each frequency
  → Any asymmetry between port and starboard wings

AFTER THIS CARD:
  • Record all data in flight log
  • Address any abort conditions before proceeding to TC-02
  • Update FLAP_AMP_LIMIT_MAX_DEG if amplitude testing is successful

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] Increase vel_limit to 200 rad/s if 150 proved insufficient
  [SW] Increase FLAP_AMP_LIMIT_MAX_DEG from 85° to 96° if sector wheel extended
  [SW] Enable MotorThermalMonitor advisory at 80°C rise

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] Extend sector wheel arc from 160° to 192° for ±96° amplitude
  [HW] Switch to 0.75mm SK75 Dyneema for better compliance
  [HW] Install urethane bump stops at ±96° end stops

TEST CARD 02 — TETHERED HOVER / LIFT TEST
Phase: PHASE 1 — GROUND  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Verify the aircraft generates sufficient lift to exceed MTOW under controlled conditions. Calibrate CT from direct thrust measurement.

PRECONDITIONS:
  ✓ TC-01 completed successfully
  ✓ Load cell rated ≥10× MTOW (35N minimum) installed beneath aircraft
  ✓ Aircraft suspended 0.5m above load cell on tension line
  ✓ Safety tether prevents vehicle from exceeding 1m altitude
  ✓ Wind < 5 kt

PROCEDURE:
  1. Start at f=1.0 Hz, AMP=80°. Record lift from load cell.
  2. Increase frequency in 0.25 Hz steps to 3.0 Hz. Record lift at each step.
  3. At each frequency, hold for 10s, average reading.
  4. Repeat at AMP=90°, AMP=96° (if sector wheel permits).
  5. Record the frequency at which lift = MTOW (hover point).
  6. Record the frequency at which lift = 1.3 × MTOW (safety margin).
  7. Calculate CT from measured thrust: CT = T / (0.5 × ρ × V_stroke² × S)

SUCCESS CRITERIA:
  ✓ Aircraft achieves lift ≥ MTOW (3.448 × 9.81 = 33.8N) at some f ≤ 3 Hz
  ✓ CT value confirms or updates wave library placeholder (1.13)
  ✓ Lift scales as f² with R² > 0.95 (confirms T ∝ f² scaling)
  ✓ Lift scales as AMP² with R² > 0.90 (confirms T ∝ AMP² scaling)

ABORT CRITERIA (revert / RTB immediately):
  ✗ Tether tension > 50N (structural overload risk)
  ✗ Any structural deformation visible
  ✗ Lift does not increase monotonically with frequency

DATA TO RECORD:
  → Lift force (N) vs frequency at each amplitude — PRIMARY CT CALIBRATION
  → CT value computed from data
  → f_hover (Hz) — frequency at which lift = MTOW
  → AMP² scaling exponent (should be 2.0)

AFTER THIS CARD:
  • Update CT constant in wave library (# CAL: → measured value)
  • Update all performance predictions based on measured CT
  • Proceed to TC-03 only if hover point f_hover ≤ 2.8 Hz (margin to 3.0 Hz)

EXPANDING THIS LIMIT ENABLES:
  ↑ CT calibration unlocks all absolute performance predictions
  ↑ Measured f_hover tells us exactly how much safety margin we have
  ↑ AMP² calibration validates the ±96° thrust benefit calculation

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] Update CT_EST in mco_wave_library.py with measured value
  [SW] Update FREQ_LIMIT_MAX_HZ if hover is achievable below 2.5 Hz
  [SW] Enable the Ps target table modulation by density altitude

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] If f_hover > 2.8 Hz: extend sector wheel to ±96° IMMEDIATELY
  [HW]   (±96° reduces f_hover by factor √(1/1.35) = 0.86 → saves ~0.4 Hz margin)
  [HW] If f_hover > 3.0 Hz: aircraft cannot hover — redesign required

TEST CARD 03 — FIRST FLIGHT — CONTROLLABILITY DEMONSTRATION
Phase: PHASE 2 — FIRST FLIGHT  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Demonstrate basic controllability in all three axes. Confirm stable flight at cruise parameters. Per AC 90-89C §4.9: minimum 10-minute flight, remain within gliding distance of runway.

PRECONDITIONS:
  ✓ TC-01 and TC-02 completed successfully
  ✓ CT measured and wave library updated
  ✓ f_hover confirmed ≤ 2.8 Hz
  ✓ All preflight checks complete (see mco_preflight.py)
  ✓ Chase observer with binoculars and radio
  ✓ Emergency recovery waypoint programmed in Pixhawk
  ✓ Wind < 8 kt, gusts < 4 kt
  ✓ Visibility > 3 miles
  ✓ Ceiling > 1000 ft AGL

PROCEDURE:
  1. Arm. Initiate takeoff intent. Verify takeoff phase activates.
  2. Climb to 10m AGL at standard climb rate. Verify climb intent.
  3. Level at 10m. Verify cruise intent activates at f ≈ 1 Hz.
  4. Fly a 200m straight line at cruise speed. Observe tracking.
  5. Execute a 90° left turn. Observe bank angle and coordination.
  6. Execute a 90° right turn. Observe symmetry with left turn.
  7. Extend to 300m from launch point. Observe telemetry quality.
  8. Return to launch. Execute standard landing pattern.
  9. Land. Post-flight inspection.

SUCCESS CRITERIA:
  ✓ Aircraft climbs to 10m AGL without oscillation
  ✓ Level flight maintained ±2m altitude for 60 seconds
  ✓ Turns executed with bank ≤ 20° and no altitude loss > 3m
  ✓ Telemetry link unbroken throughout
  ✓ All motor currents within expected range
  ✓ Landing within 10m of target

ABORT CRITERIA (revert / RTB immediately):
  ✗ Any uncontrolled oscillation in pitch, roll, or yaw
  ✗ Altitude loss > 3m during level flight attempt
  ✗ Motor current spike > 30A on any axis
  ✗ Telemetry link loss > 2 seconds
  ✗ Any structural noise (wing flutter, rope snap)
  ✗ GPS lock lost

DATA TO RECORD:
  → Actual vs commanded trajectory (GPS)
  → Motor currents at cruise (CT calibration confirmation)
  → Actual cruise frequency achieved
  → Pitch, roll, yaw angles throughout flight
  → Battery voltage sag at various loads

AFTER THIS CARD:
  • Full structural inspection after first flight
  • Compare actual cruise frequency to TC-02 prediction
  • Proceed to TC-04 only after ≥5 successful flights at this level

TEST CARD 04 — STALL CHARACTERISTICS — CLEAN CONFIGURATION
Phase: PHASE 3 — ENVELOPE EXPANSION  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Establish the actual stall speed and stall behaviour in clean configuration. Per AC 90-89C §6.3: 'Approach the stall gradually. Do not attempt to stall the aircraft abruptly.'

PRECONDITIONS:
  ✓ ≥5 successful Phase 2 flights completed
  ✓ Minimum altitude 200m AGL for all stall tests
  ✓ Emergency recovery mode tested and confirmed active
  ✓ Wind < 6 kt, smooth air (no thermals)
  ✓ Test area clear of obstacles

PROCEDURE:
  1. Climb to 200m AGL.
  2. Set cruise intent. Note airspeed (V_cruise).
  3. Reduce frequency gradually in 0.1 Hz steps.
  4. At each step: hold for 5 seconds, record airspeed and altitude.
  5. Approach stall: note buffet onset (if any) and Vs.
  6. At first sign of stall (altitude loss > 2m in 2s): immediately activate CF-1 stall recovery.
  7. Record recovery altitude lost.
  8. Repeat 3 times. Average the stall speed.
  9. Compare to predicted Vs = 4.85 m/s (9.42 kt).

SUCCESS CRITERIA:
  ✓ Stall speed within ±15% of predicted 4.85 m/s
  ✓ CF-1 recovery complete within 10m altitude loss
  ✓ No structural sounds during stall approach or recovery
  ✓ Consistent stall speed across 3 repetitions (±5%)

ABORT CRITERIA (revert / RTB immediately):
  ✗ Altitude loss > 20m before recovery completes
  ✗ Any structural noise or visible wing deformation
  ✗ Uncommanded roll at stall > 30°
  ✗ Recovery altitude < 50m AGL

DATA TO RECORD:
  → Actual stall speed V_S1 (m/s and kt) — UPDATE WAVE LIBRARY
  → Altitude lost in stall recovery (m)
  → CF-1 recovery time (seconds)
  → Any stall warning characteristics (buffet, pitch drop)
  → Comparison: actual vs predicted stall speed

AFTER THIS CARD:
  • Update VS_KT in wave library with measured value
  • Update stall_speed_check() safety margins if Vs differs > 10% from prediction
  • Establish 1.3×Vs as minimum manoeuvre speed
  • Proceed to TC-05 (stall in turns) only after 3 clean TC-04 results

EXPANDING THIS LIMIT ENABLES:
  ↑ Measured Vs calibrates all subsequent stall margin calculations
  ↑ Recovery altitude tells us how much AGL margin we need for stall tests
  ↑ Clean stall must be established before any loaded or banked stall attempts

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] If Vs < 4.5 m/s: lower VS_KT — more CL than predicted. Increase CF-1 frequency ceiling by 0.2 Hz
  [SW] If Vs > 5.5 m/s: raise VS_KT — less CL than predicted. Reduce stall_margin_min_ms safety gate accordingly
  [SW] Tune stall_speed_check() STALL_APPROACH_FREQ_HZ to measured f_hover

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] If recovery takes > 15m altitude: extend sector wheel to ±96° for faster burst recovery thrust
  [HW] If stall is abrupt (no buffet): add covert flap rows to W1+W2 to soften stall onset character

TEST CARD 05 — MAXIMUM SPEED (VNE APPROACH) — SPEED ENVELOPE
Phase: PHASE 3 — ENVELOPE EXPANSION  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Establish the actual Vne by approaching maximum speed incrementally and checking for flutter, control reversal, or structural instability. Per EAA Stage Three: 'Flutter is the most dangerous characteristic to explore. Approach with extreme caution.'

PRECONDITIONS:
  ✓ ≥10 successful flights. Stall speed measured (TC-04 complete).
  ✓ All structural fasteners inspected and re-torqued
  ✓ Wing skin inspected for delamination or loose sections
  ✓ Minimum altitude 300m AGL for all high-speed tests
  ✓ All wings stowed (210°) and locked before sprint

PROCEDURE:
  1. Climb to 300m. Set stow intent.
  2. Verify W1+W2 stowed, W3+W4 in sprint configuration.
  3. Accelerate to V_cruise + 5 mph. Hold 5 seconds. Check for vibration.
  4. If smooth: accelerate to V_cruise + 10 mph. Hold 5 seconds.
  5. Continue in 5 mph steps.
  6. At each speed: check IMU vibration, wing visual inspection via camera.
  7. If ANY vibration increase or unusual behaviour: STOP, decelerate gently.
  8. Establish Vne as the highest speed with no vibration, flutter, or control anomaly. Set as Vne - 10% for initial operations.
  9. Do not chase a specific target Vne — find the actual limit.

SUCCESS CRITERIA:
  ✓ Speed increased in controlled steps with no flutter observed
  ✓ IMU vibration RMS stays below 2× cruise baseline at all speeds
  ✓ No control reversal or uncommanded motion at any tested speed
  ✓ Wing skin remains attached at all tested speeds

ABORT CRITERIA (revert / RTB immediately):
  ✗ IMU vibration suddenly increases (flutter onset signal)
  ✗ Uncommanded roll or pitch excursion > 15°
  ✗ Any structural sound from wing or drive
  ✗ Control response becomes sluggish or reversed
  ✗ Battery voltage drops below safe minimum

DATA TO RECORD:
  → Airspeed at each test point (GPS-derived TAS)
  → IMU vibration RMS at each speed step
  → Motor current at each speed step
  → Actual Vne established (mph and kt)
  → Photos/video of wings at each speed step

AFTER THIS CARD:
  • Set Vne in wave library operating limits
  • Establish Vno (normal operating speed) = 0.9 × Vne
  • Establish caution speed range (yellow arc) from Vno to Vne

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] Sweep configuration at sprint — test W1+W2 at different stow angles to find lowest-drag stow position
  [SW] Adjust sprint_phase_offset for best thrust at high speed
  [SW] Implement flutter monitoring in flight_recorder (track IMU FFT peaks)

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] If flutter onset below 80 mph: add mass balance weights to W3+W4 tips
  [HW] If flutter onset below 60 mph: wing spar stiffness review required
  [HW] Oratex skin tension adjustment — higher tension raises flutter speed
  [HW] TE stow slot receivers reduce stowed-wing buffet → raise Vne

TEST CARD 06 — CLIMB PERFORMANCE — VY AND VX
Phase: PHASE 3 — ENVELOPE EXPANSION  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Establish best rate of climb speed (Vy) and best angle of climb speed (Vx). Per AC 90-89C §5.7: 'Climbs and descents should be gradually explored.'

PRECONDITIONS:
  ✓ Stall speed confirmed (TC-04 complete)
  ✓ Air smooth, wind < 5 kt
  ✓ Start altitude 50m AGL, climb ceiling 300m AGL

PROCEDURE:
  1. At V = 1.3×Vs: climb at max frequency (3.0 Hz). Record altitude gain per minute.
  2. Increase speed in 5 mph steps up to 80% Vne.
  3. At each speed: hold heading, record altitude gain rate over 30s.
  4. Plot climb rate vs airspeed → Vy is peak of the curve.
  5. At Vy: hold altitude, reduce frequency until rate = 100 fpm. Record frequency and speed → confirms Ps model.
  6. At 1.3×Vs: repeat with maximum available climb angle. Record ground covered per foot of altitude → Vx.

SUCCESS CRITERIA:
  ✓ Vy identified with R/C variation > 50 fpm between adjacent test points
  ✓ Vx identified (steepest angle speed, lower than Vy)
  ✓ Measured R/C within 30% of predicted (CT now calibrated)

ABORT CRITERIA (revert / RTB immediately):
  ✗ Altitude below 50m AGL at any point
  ✗ Motor current > 30A during max climb

DATA TO RECORD:
  → R/C (fpm) vs airspeed table — VY and VX values
  → Maximum climb rate achieved (fpm) — UPDATE PERF MODEL
  → Frequency at Vy — confirms f-efficiency relationship
  → Time to climb 200m from 50m — absolute performance datum

AFTER THIS CARD:
  • Update mco_performance_model.py with measured Vy, Vx, R/C
  • Enable PhaseOptimiser (it can now run safely)

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] Once Vy confirmed: set CLIMB_TARGET_V_MS in wave library
  [SW] Boyd controller Ps targets calibrated to actual R/C vs Ps relationship
  [SW] Enable CascadeOptimiser after ≥10 flights with confirmed Vy

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] If R/C < 200 fpm: sector wheel extension to ±96° is the priority fix
  [HW] If R/C > 500 fpm: explore higher AGL ceiling testing

TEST CARD 07 — SERVICE CEILING APPROACH
Phase: PHASE 3 — ENVELOPE EXPANSION  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Establish the service ceiling (altitude where R/C drops to 100 fpm) per AC 90-89C §7.2. Per FAA: 'Service ceiling tests should be performed gradually, climbing in increments.'

PRECONDITIONS:
  ✓ Vy and R/C established (TC-06 complete)
  ✓ At least 20 successful flights
  ✓ Full battery, checked voltage
  ✓ No wind, ISA conditions preferred
  ✓ Pixhawk barometer altitude calibrated against GPS pressure altitude

PROCEDURE:
  1. Climb at Vy to 100m AGL. Record R/C at this altitude.
  2. Continue climb to 200m, 400m, 600m, 800m, 1000m.
  3. At each altitude: stabilise for 30s, record R/C over 60s.
  4. Plot R/C vs altitude. Extrapolate to find 100 fpm altitude.
  5. Service ceiling = altitude where R/C = 100 fpm.
  6. Do NOT attempt to actually reach service ceiling in first tests — extrapolate from the trend.
  7. Verify the ρ_ratio × thrust relationship matches ISA predictions.

SUCCESS CRITERIA:
  ✓ R/C decreases monotonically with altitude (confirms model)
  ✓ Service ceiling extrapolated from 5+ data points with R² > 0.90
  ✓ Measured R/C at each altitude within 25% of ρ-scaled prediction

ABORT CRITERIA (revert / RTB immediately):
  ✗ Battery voltage drops below safe minimum
  ✗ R/C drops below 200 fpm (approaching ceiling — RTB)
  ✗ GPS altitude > 1200m AGL without prior approval

DATA TO RECORD:
  → R/C (fpm) at each altitude
  → Extrapolated service ceiling (m and ft)
  → ρ_ratio at each altitude vs R/C reduction — validate model

AFTER THIS CARD:
  • Update mco_performance_model.py with measured ceiling
  • Confirm ±96° amplitude would extend ceiling by predicted ~7,500 ft

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] density_altitude() function feed from Pixhawk barometer — confirm active
  [SW] Ps_target table modulation by density altitude — enable and calibrate

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] Sector wheel to ±96°: predicted +7,500 ft ceiling gain
  [HW] Reducing MTOW by removing non-essential payload also raises ceiling

TEST CARD 08 — FLUTTER INVESTIGATION — STRUCTURAL LIMIT
Phase: PHASE 3 — ENVELOPE EXPANSION  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Per AC 90-89C §6.7-6.8: Flutter is the most critical structural test. It occurs suddenly and can cause catastrophic structural failure within seconds. The goal is to find flutter ONSET — not to experience full flutter. Approach with extreme caution.

PRECONDITIONS:
  ✓ Vne approach testing (TC-05) complete
  ✓ At least 25 flights completed
  ✓ Wings fully inspected: all ribs, spars, skin secure
  ✓ All wing joints torqued to spec (AN4 hardware)
  ✓ IMU high-frequency logging enabled (200 Hz minimum)
  ✓ Video camera on wings during test
  ✓ Start at 60% of TC-05 maximum speed. Increment 5 mph per pass.

PROCEDURE:
  1. Confirm aircraft is at established Vno (90% of TC-05 Vne).
  2. FLUTTER MONITORING: IMU FFT output should show no peak > 2× background in 10-50 Hz range.
  3. Accelerate to Vno + 5 mph. Hold 5 seconds. Examine FFT.
  4. If clean: Vno + 10 mph. If any FFT peak emerges: STOP.
  5. Continue to established Vne in 5 mph steps.
  6. If flutter onset detected (FFT peak rise): smoothly reduce speed. Do NOT abruptly pitch up.
  7. Report: flutter speed (if found), or confirm clean to Vne.
  8. Do not exceed Vne during this test.

SUCCESS CRITERIA:
  ✓ No flutter detected below Vne
  ✓ IMU FFT shows no emerging peaks in 10-50 Hz range at any speed
  ✓ Aircraft handled normally at all tested speeds

ABORT CRITERIA (revert / RTB immediately):
  ✗ ANY IMU FFT peak suddenly rises > 2× background: decelerate NOW
  ✗ Visible wing oscillation on camera
  ✗ Any structural sound from wings
  ✗ Control feel changes at any speed

DATA TO RECORD:
  → IMU FFT spectra at each speed (peak frequency, amplitude)
  → Video of wings at each speed step
  → Flutter onset speed if observed (mph)
  → Type of flutter if observed (bending, torsion, coupled)

AFTER THIS CARD:
  • If flutter onset observed: lower Vne to 85% of flutter speed
  • Report flutter details to design team for structural analysis

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] Implement real-time FFT flutter monitor in flight_recorder.py
  [SW] Auto-decelerate if 10-50 Hz IMU peak exceeds threshold
  [SW] Log FFT data every 0.5 seconds during high-speed flight

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] If flutter below 80 mph: add mass balance to wing tips (small weights at 20-25% chord from LE at tip)
  [HW] If torsional flutter: increase trailing edge stiffness (spar to TE rod)
  [HW] Reduce chord if flutter consistently below 60 mph

TEST CARD 09 — LOAD FACTOR / G-FORCE ENVELOPE
Phase: PHASE 3 — ENVELOPE EXPANSION  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Per EAA Stage Three: 'Testing to a modest 3G limit should be sufficient for most non-aerobatic lightplanes.' Establish the MCO's actual structural limit by approaching it in 0.25G increments through banked turns.

PRECONDITIONS:
  ✓ TC-04 (stall) and TC-05 (Vne) complete
  ✓ Minimum 300m AGL
  ✓ IMU g-load logging active
  ✓ Approach load factor in banked turns at 1.3×Vs
  ✓ Bank angle: 30°=1.15g, 45°=1.41g, 60°=2.00g, 75°=3.86g

PROCEDURE:
  1. Level flight at 1.3×Vs. Initiate 30° bank turn. Note g-load.
  2. Recovery. Wait 30 seconds. Inspect for any anomalies.
  3. Increase to 45° bank. Hold for 5 seconds. Note g-load and stall speed.
  4. Recovery. Structural inspection via camera.
  5. Increase to 60° bank (2.0G). This is the initial design limit.
  6. If clean and no anomalies: attempt 65° bank (2.37G).
  7. Stop at 2.5G initially. This is conservative — MCO's SF is 15× on spar.
  8. On subsequent flights, expand to 3.0G if all checks pass.

SUCCESS CRITERIA:
  ✓ Aircraft controllable at all tested bank angles
  ✓ No structural noise or anomalies during turns
  ✓ Stall speed in turns matches n = 1/cos(bank) prediction
  ✓ Recovery clean at all tested load factors

ABORT CRITERIA (revert / RTB immediately):
  ✗ Any structural sound during banked turn
  ✗ Uncontrolled roll or pitch excursion
  ✗ Altitude loss > 30m during recovery
  ✗ IMU g-load exceeds 3.5G (structural margin)

DATA TO RECORD:
  → Peak g-load at each bank angle
  → Stall speed in turns vs prediction (n = 1/cos(bank)) — PHAK validation
  → Maximum tested g-load without anomaly
  → Recovery altitude lost at each test point

AFTER THIS CARD:
  • Establish maximum g-load for normal operations (2.5G initial)
  • Update manoeuvre envelope in wave library
  • Stall in turns data validates PHAK formulas in wave library

SOFTWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [SW] stall_speed_check() turn stall formula already implemented — validate
  [SW] Adjust stall_margin_min_ms safety gate based on measured turn stall data
  [SW] Enable banked stall protection (reduce freq before entering high-bank)

HARDWARE CHANGES TO PUSH THIS LIMIT FURTHER:
  [HW] Higher g-limit requires spar review (rattan to CF tube upgrade for 1A)
  [HW] For MCO-1A: AN4 hardware at all joints is mandatory before 2G testing

TEST CARD 10 — CASCADE PHASE OPTIMISATION
Phase: PHASE 4 — PERFORMANCE  |  Aircraft: MCO-1D
============================================================

OBJECTIVE:
  Enable the PhaseOptimiser and CascadeOptimiser. Systematically map the Ps response surface over the (phase_offset, diff_sweep) parameter space.

PRECONDITIONS:
  ✓ ≥15 successful flights. All Phase 3 cards complete.
  ✓ CT and Vs measured and wave library updated.
  ✓ PhaseOptimiser enabled (PHASE_OPT_ENABLED = True)
  ✓ Smooth air, consistent conditions for reliable Ps measurement

PROCEDURE:
  1. Enable PhaseOptimiser (CH6 toggle).
  2. Fly standard cruise for 20 minutes. Allow optimiser to run.
  3. Check optimiser log: which phase offset improved Ps?
  4. On next flight: enable CascadeOptimiser with best phase from above.
  5. Fly 20 minutes. Allow 2D (phase, diff_sweep) search to run.
  6. Repeat over ≥5 flights. Allow convergence.
  7. Report: optimal phase, optimal diff_sweep, Ps improvement vs nominal.

SUCCESS CRITERIA:
  ✓ PhaseOptimiser converges within ±5° of a stable optimum
  ✓ CascadeOptimiser converges to a stable (phase, diff_sweep) pair
  ✓ Ps improvement at optimum > 5% vs nominal parameters

LIMIT EXPANSION STRATEGY SUMMARY
============================================================

Every limit has three expansion pathways. After each test card
confirms a limit, the following options are available:

1. SOFTWARE EXPANSION (fastest, lowest risk):
   • Tune constants in wave library (VS_KT, FREQ_LIMIT_MAX_HZ, etc.)
   • Enable optimiser tiers (Phase→Cascade→Adaptive)
   • Refine Boyd Ps targets based on measured performance
   • Implement flutter monitor FFT in flight_recorder

2. FIRMWARE / ALGORITHM EXPANSION (medium risk):
   • Adjust safety gate thresholds based on measured margins
   • Enable additional flight modes (GL-8, GL-9, stoop, zoom)
   • Implement adaptive cascade phase scheduling
   • Enable density-altitude-corrected thrust targets

3. HARDWARE EXPANSION (highest impact, requires rebuild):
   • Sector wheel to 192° arc (±96°) — +35% thrust
   • Fuselage narrowed to 150mm — enables clap-and-fling
   • Wing mass balance — raises flutter speed
   • Covert flaps on W1+W2 (groove VGs) — improves CL
   • Stow slot receivers — raises Vne by reducing stowed-wing drag
   • KTM 790 bolt-ons — +34% continuous power for MCO-R

THE GOLDEN RULE OF ENVELOPE EXPANSION:
  "Never more than one change at a time. Test. Confirm.
